In `internal/tui/streaming/agent_loop.go`, fix the iterator lifecycle management:

1. Add `"sync"` to imports if not present.

2. Replace the iterator close pattern (around lines 210-235). The current code has:
   - A goroutine that calls `iterator.Close()` on context cancellation
   - Main loop that calls `iterator.Close()` on error paths (lines 230-231, 234)
   - Neither path signals the other, causing double-close risk and goroutine leak

   Replace with a `sync.Once`-guarded close function:

   ```go
   // After creating the iterator (after line 209):
   var iteratorCloseOnce sync.Once
   closeIterator := func() {
       iteratorCloseOnce.Do(func() {
           _ = iterator.Close()
       })
   }

   // Replace the goroutine (lines 210-217) with:
   iterDone := make(chan struct{})
   go func() {
       select {
       case <-ctx.Done():
           closeIterator()
       case <-iterDone:
       }
   }()

   // Replace all `_ = iterator.Close()` calls in the main loop with `closeIterator()`:
   // Line 230-231: replace `_ = iterator.Close()` with `closeIterator()`
   // Line 234: replace `_ = iterator.Close()` with `closeIterator()`
   ```

3. After the main for-loop exits (after the `}` that closes the for-loop around line 260), add cleanup:
   ```go
   close(iterDone)
   ```

   This ensures the goroutine is always signaled to exit, preventing goroutine leaks on ALL exit paths (normal completion, error, and context cancellation).
