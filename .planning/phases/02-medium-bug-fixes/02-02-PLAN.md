**Fix M2 — pkg/taskrunner/runner.go (lines 283-284):**

The `OnTaskUpdate` callback is called while `r.mu` is held. If the callback calls back into `Runner.Status()` or `Runner.Tasks()`, it deadlocks because Go's `sync.RWMutex` is not reentrant.

Fix: Capture the state needed for the callback while holding the lock, then call the callback AFTER releasing the lock.

Find the pattern where `r.OnTaskUpdate` is called inside a locked section. Restructure to:

```go
r.mu.Lock()
// ... perform state mutations ...
// Capture snapshot for callback
taskSnapshot := r.tasks[id] // or whatever state the callback needs
r.mu.Unlock()

// Call callback outside lock
r.OnTaskUpdate(taskSnapshot)
```

If the callback needs the full task list, snapshot it:
```go
r.mu.Lock()
// ... mutations ...
snapshot := make([]Task, len(r.tasks))
copy(snapshot, r.tasks)
r.mu.Unlock()
r.OnTaskUpdate(snapshot...)
```

**Fix M3 — internal/tools/devserver.go (lines 344-362):**

After deleting an entry from the map and releasing the lock, the code accesses `entry.cmd.Process` without holding `entry.mu`. This races with the `monitorCrash()` goroutine.

Fix: Hold `entry.mu` while accessing `entry.cmd.Process`, or capture the process before releasing the map lock:

```go
d.mu.Lock()
entry, ok := d.processes[id]
if ok {
    delete(d.processes, id)
}
d.mu.Unlock()

if ok && entry != nil {
    entry.mu.Lock()
    proc := entry.cmd.Process
    entry.mu.Unlock()
    if proc != nil {
        // use proc safely
    }
}
```

**Fix M13 — internal/tools/edit.go (lines 103-112):**

The TOCTOU occurs because `os.Stat` checks file size, then `os.ReadFile` reads the file separately. The file could be swapped between the two calls.

Fix: Remove the Stat check entirely. Read the file first, then check size on the obtained data:

```go
data, err := os.ReadFile(path)
if err != nil {
    return fmt.Errorf("reading file: %w", err)
}
if len(data) > MaxFileSize {
    return fmt.Errorf("file exceeds maximum size of %d bytes: %w", MaxFileSize, ErrFileTooLarge)
}
```

This eliminates the TOCTOU because the size check is on the data already read.

**Fix M14 — internal/tools/bash.go (lines 477-490):**

The current blocklist uses simple string matching which can be bypassed:
- `rm -r -f /` (separate args) bypasses `rm -rf /` pattern
- `rm$'\t'-rf /` bypasses via tab character

Fix: Add a normalization step before matching. Create a helper function:

```go
// normalizeCommandArgs normalizes whitespace and removes shell quoting
// to prevent bypass via argument splitting or obfuscation.
func normalizeCommandArgs(cmd string) string {
    // Replace tabs and multiple spaces with single space
    normalized := strings.ReplaceAll(cmd, "\t", " ")
    normalized = strings.ReplaceAll(normalized, "\r", " ")
    // Collapse multiple spaces
    for strings.Contains(normalized, "  ") {
        normalized = strings.ReplaceAll(normalized, "  ", " ")
    }
    return strings.TrimSpace(normalized)
}
```

Then in `checkDangerousCommand`, normalize before matching:

```go
func checkDangerousCommand(command string) (string, bool) {
    normalized := normalizeCommandArgs(strings.ToLower(command))
    // ... rest of matching logic uses normalized ...
}
```

Also add a pattern for `rm` with separate `-r` and `-f` flags:

Add to `dangerousCommandPatterns`:
```go
{"rm -r -f", "recursive force delete"},
{"rm -f -r", "recursive force delete"},
```
