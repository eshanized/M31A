# Plan 1.4 — OpenCode Zen Client

Implement the OpenCode Zen HTTP client implementing `LLMProvider`. Structurally identical to the OpenRouter client but with a different base URL and slightly different field mappings.

---

## Task 01.4 — Create Zen Client

**Description:** Create `internal/provider/zen/client.go` with all methods of the `LLMProvider` interface.

<read_first>
- internal/provider/openrouter/client.go (use as reference — same structure, different base URL)
- internal/provider/interface.go (LLMProvider, ChatRequest, ToolDefinition)
- internal/provider/cache.go (ModelCache)
- internal/provider/sse.go (SSEParser)
- internal/provider/reasoning.go (GetReasoningConfig, ApplyReasoningParams, ParseSSEChunk)
- internal/types/types.go (ModelInfo, StreamIterator, StreamChunk, Usage, HealthStatus)
- internal/types/constants.go (ModelCacheTTL, HTTPDialTimeout)
- internal/errors/errors.go (ErrInvalidKey, ErrProviderUnreachable, ErrRateLimited, ErrContextExceeded, ErrModelNotFound)
</read_first>

<action>
Create `internal/provider/zen/client.go`:

**Package declaration:** `package zen`

**Struct:**
```go
type Client struct {
    apiKey     string
    baseURL    string
    httpClient *http.Client
    cache      *provider.ModelCache
}
```

**Imports:** Same as OpenRouter client — `context`, `encoding/json`, `fmt`, `io`, `net`, `net/http`, `strings`, `time`, `github.com/eshanized/M31A/internal/errors`, `github.com/eshanized/M31A/internal/provider`, `github.com/eshanized/M31A/internal/types`

**`New(apiKey string) (*Client, error)`:**
- Same validation as OpenRouter: empty key → `m31errors.ErrInvalidKey`
- Same HTTP client: 30s dial timeout, no body read timeout
- `baseURL = "https://opencode.ai/zen/v1"`
- `cache = provider.NewModelCache(types.ModelCacheTTL)`

**`Name() string`:**
- Return `"zen"`

**`FetchModels(ctx context.Context) ([]types.ModelInfo, error)`:**
- GET `baseURL + "/models"`
- Headers: `Authorization: Bearer <apiKey>`, `User-Agent: M31A/<Version>`
- Zen API returns a model list array directly (not wrapped in `{"data":...}`). Parse JSON array.
- Field mapping (Zen-specific):
  - `id` → `ModelInfo.ID`
  - `name` → `ModelInfo.Name`
  - `description` → `ModelInfo.Description` (if field exists)
  - `context_length` or `max_context` → `ModelInfo.ContextLength` (int64)
  - `pricing.prompt` or `pricing.prompt_token` → `ModelInfo.Pricing.InputPerMToken` (multiply by 1,000,000)
  - `pricing.completion` or `pricing.completion_token` → `ModelInfo.Pricing.OutputPerMToken` (multiply by 1,000,000)
  - `TopProvider` → set to `"zen"` for all models
  - `Capabilities` → detect from `capabilities` or `features` field if present
- Same cache behavior as OpenRouter: populate on success, return stale on error

**`ChatCompletionStream(ctx context.Context, req provider.ChatRequest) (*types.StreamIterator, error)`:**
- Same POST logic as OpenRouter to `baseURL + "/chat/completions"`
- Same body construction: model, messages, max_tokens, stream: true, tools, reasoning params
- Headers: `Authorization: Bearer <apiKey>`, `Content-Type: application/json`, `Accept: application/json`, `User-Agent: M31A/<Version>`
- **No HTTP-Referer or X-Title headers** (Zen doesn't require them)
- Same error mapping (429 → ErrRateLimited, 401 → ErrInvalidKey, 503 → ErrProviderUnreachable, 400 with context → ErrContextExceeded)
- Same SSE parsing via `provider.NewSSEParser` + `provider.ParseSSEChunk`

**`EstimateCost(usage types.Usage) float64`:**
- Same limitation as OpenRouter: no model ID in interface signature → return 0
- Document as known interface limitation

**`HealthCheck(ctx context.Context) types.HealthStatus`:**
- GET `baseURL + "/models"` (catalog fetch doubles as auth validation)
- Headers: `Authorization: Bearer <apiKey>`, `User-Agent: M31A/<Version>`
- Same latency thresholds: 200ms → "live", 500ms → "slow", else → "offline"
- A successful 200 with model list = auth validated

**`GetModel(id string) (*types.ModelInfo, error)`:**
- Same as OpenRouter: check cache, return model or `ErrModelNotFound`
</action>
