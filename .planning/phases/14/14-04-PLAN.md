<objective>
Persist workflow state (goal, current phase, discuss questions) to
`session.json` so that closing the app mid-workflow doesn't abandon
all progress. On startup, the TUI detects a non-idle workflow state
and shows a resume option. New `/workflow resume` command restarts
the workflow at the saved phase.

**Purpose:** Resolve audit issue **D-06** (MEDIUM — workflow state
non-persistent). Currently `m.workflowEngine`, `m.workflowGoal`,
`m.discussQuestions`, and `m.currentPhase` are in-memory only. Closing
the terminal mid-workflow abandons all progress. The fix adds
persistence to `session.json` and a resume mechanism.

**Output:** Extended `Session` struct (new fields), new
`UpdateWorkflowState` / `LoadWorkflowState` methods on `Manager`,
updated `app.go` to call these on phase transitions and on startup,
new `/workflow resume` slash command, and tests.
</objective>

    In `pkg/session/manager.go`, add two new methods on `*Manager`:

    ```go
    // UpdateWorkflowState persists the workflow's current goal, phase,
    // and pending discuss questions to session.json. This is called
    // on every phase transition by the TUI.
    //
    // Returns an error if the session doesn't exist or the write fails.
    // The write is atomic (temp file + rename) so a crash mid-write
    // leaves the existing session.json intact.
    func (m *Manager) UpdateWorkflowState(id, goal string, phase types.WorkflowPhase, questions []string) error {
        session, err := m.LoadSession(id)
        if err != nil {
            return fmt.Errorf("UpdateWorkflowState: load session: %w", err)
        }
        session.SetWorkflowState(goal, phase, questions)
        return m.saveSessionAtomic(session)
    }

    // LoadWorkflowState reads just the workflow state fields from
    // session.json. Returns the persisted values, or zero values
    // (empty goal, PhaseIdle, empty questions) if the session
    // doesn't exist or the workflow state is unset.
    func (m *Manager) LoadWorkflowState(id string) (goal string, phase types.WorkflowPhase, questions []string, err error) {
        session, err := m.LoadSession(id)
        if err != nil {
            if errors.Is(err, ErrSessionCorrupted) {
                // Session doesn't exist yet — return zero values
                return "", types.PhaseIdle, nil, nil
            }
            return "", types.PhaseIdle, nil, err
        }
        return session.WorkflowState()
    }

    // saveSessionAtomic writes the session to disk atomically.
    // Used by UpdateWorkflowState; also a building block for future
    // session-modification operations.
    func (m *Manager) saveSessionAtomic(session *Session) error {
        data, err := json.Marshal(session)
        if err != nil {
            return fmt.Errorf("cannot marshal session: %w", err)
        }
        return m.atomicWrite(m.sessionJSONPath(session.ID), data)
    }
    ```

    Add `"errors"` to the imports at the top of `manager.go` if not
    already present.

    Note: `UpdateWorkflowState` does a full `LoadSession` + modify +
    write cycle. This is fine for the typical workflow rate (a few
    phase transitions per minute). If a future optimization is needed,
    a partial-write method that updates only the relevant JSON fields
    can be added without changing the public API.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TUI → session.json | TUI writes workflow state via UpdateWorkflowState. State is local to the user's home directory; no cross-user access. |
| session.json → TUI on startup | TUI reads workflow state via LoadWorkflowState. State is local; no network exposure. |
| User → /workflow resume | User explicitly invokes resume. No untrusted source can trigger a phase transition. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-04-01 | Tampering | session.json modified by another process | mitigate | Atomic write (temp + rename). Read fails gracefully with ErrSessionCorrupted. Phase 5 already has session.json schema validation. |
| T-14-04-02 | Information Disclosure | Workflow goal in session.json | accept | Goal is the user's own project description; same trust as session messages. Stored in `~/.m31a/sessions/<id>/` (user-only). |
| T-14-04-03 | Spoofing | /workflow resume with arbitrary phase | mitigate | ResumePhase is set by the engine's persisted state, not user input. The slash command only passes through the loaded phase. |
| T-14-04-04 | Denial of Service | Persistence failure aborts workflow | accept | persistWorkflowState logs but does not return the error; the workflow continues in this session. |
| T-14-04-05 | Race Condition | Two concurrent UpdateWorkflowState calls | mitigate | session.json is written atomically per call. Last-writer-wins; not a security issue (single-user app). |
</threat_model>
