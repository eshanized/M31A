<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Workflow engine → TUI | Engine emits PhaseResultMsg{Tasks: [...]}. TUI trusts tasks are well-formed (validation already done by engine). |
| User → TUI | User accepts/rejects/edits plan. TUI displays state and emits AppMsg on actions. |
| TUI → Engine | TUI calls RunPhaseCmd(phase, goal). Engine trusts the goal string and phase enum. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-02-01 | Tampering | PlanModel dimensions in command | accept | Width/height are display-only; no security boundary. |
| T-14-02-02 | Denial of Service | User never accepts plan | accept | User can always type `/phase` to manually advance. No infinite hang because the user has the slash command escape hatch. |
| T-14-02-03 | Spoofing | AppMsg from any source | mitigate | AppMsg is a Bubble Tea message; only `Update()` handlers and `tea.Cmd` return values produce them. No external sender. |
| T-14-02-04 | Information Disclosure | Plan tasks rendered | accept | Plan is the user's own project; not sensitive. |
| T-14-02-05 | Race Condition | Auto-advance removed | accept | Each phase now waits for user confirmation; no race. |
</threat_model>
