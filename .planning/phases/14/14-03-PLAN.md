<objective>
Synchronize the workflow message drainer with the per-phase lifecycle.
Add a `phaseGen` generation counter and a per-phase `msgDone` channel
to `AppState`. The drainer selects on `msgCh`, `msgDone`, and a 100ms
poll timer. The runner closes `msgDone` after emitting the final
`PhaseResultMsg`. The drainer captures the current `phaseGen` at spawn
and stops if the counter changes (a new phase started).

**Purpose:** Resolve audit issue **D-04** (HIGH — `msgChan` race). The
current code sets `app.msgChan = nil` then immediately creates a new
channel; the old drainer sees `nil` and returns, but messages in the
old channel may be lost. There is also a race window between
"drainer checks `app.msgChan == nil`" and "new drainer is being
created." The fix replaces this with explicit per-phase lifecycle
synchronization.

**Output:** Modified `app.go` adding `phaseGen` and `msgDone` fields,
updating `RunPhaseCmd` to create the done channel and increment the
gen, updating `workflowMsgDrainer` to select on the new fields, and
updating `runner` to close `msgDone` after the final result. New
tests for synchronization behavior.
</objective>

    ```go
    func RunPhaseCmd(app *AppState, phase types.WorkflowPhase, goal string) tea.Cmd {
        // Cancel any previous phase's context to stop lingering goroutines
        if app.workflowCancel != nil {
            app.workflowCancel()
        }

        // Increment phase generation FIRST so any drainer from the
        // previous phase sees the change and stops.
        app.phaseGen++

        // Close the OLD msgDone (if any) to signal the old drainer to stop.
        // The old channel reference is left in place until the drainer
        // returns; we don't nil it out because the drainer might still
        // be reading from it.
        if app.msgDone != nil {
            select {
            case <-app.msgDone:
                // Already closed
            default:
                close(app.msgDone)
            }
        }

        // Create new per-phase channels
        msgCh := make(chan tea.Msg, 256)
        doneCh := make(chan struct{})
        app.msgChan = msgCh
        app.msgDone = doneCh

        // Create a cancellable context for this phase
        ctx, cancel := context.WithCancel(context.Background())
        app.workflowCtx = ctx
        app.workflowCancel = cancel

        // Capture the current phaseGen for the drainer
        currentGen := app.phaseGen

        eng := app.workflowEngine
        eng.SetMsgEmitter(&channelEmitter{ch: msgCh})

        runner := func() tea.Msg {
            defer close(doneCh)  // <-- signal drainer when done

            result, err := eng.RunPhase(ctx, phase, goal)
            cancel() // Ensure cleanup

            if err != nil {
                return PhaseResultMsg{Phase: phase, Error: err.Error()}
            }
            if result == nil {
                return PhaseResultMsg{Phase: phase, Error: "nil result"}
            }

            // Emit PlanReadyMsg when the plan phase completes successfully.
            if phase == types.PhasePlan && result.Success && len(result.Tasks) > 0 {
                select {
                case msgCh <- PlanReadyMsg{
                    Tasks:        result.Tasks,
                    CostEstimate: fmt.Sprintf("%d tasks", len(result.Tasks)),
                    TimeEstimate: "",
                }:
                case <-time.After(500 * time.Millisecond):
                    slog.Warn("dropped PlanReadyMsg: channel full")
                }
            }

            return PhaseResultMsg{
                Phase:               phase,
                Tasks:               result.Tasks,
                Messages:            result.Messages,
                Success:             result.Success,
                Error:               result.Error,
                NeedsAnswers:        result.NeedsAnswers,
                RequiresManualInput: result.RequiresManualInput,
                DurationMs:          result.DurationMs,
            }
        }

        // Drainer captures the gen at spawn and stops if it changes.
        drainer := func() tea.Cmd {
            return workflowMsgDrainer(app, currentGen, doneCh)
        }

        return tea.Batch(runner, drainer())
    }
    ```

    Replace `workflowMsgDrainer` (lines 387-402):

    ```go
    // workflowMsgDrainer returns a tea.Cmd that reads one message from
    // the workflow message channel. Captures the phaseGen at spawn;
    // if the gen changes (a new phase started), the drainer returns nil.
    // Selects on msgCh, msgDone, and a 100ms poll timer to ensure
    // forward progress even when no messages are pending.
    func workflowMsgDrainer(app *AppState, gen int, done chan struct{}) tea.Cmd {
        return func() tea.Msg {
            // If the phase has been superseded, stop draining.
            if app.phaseGen != gen {
                return nil
            }
            // If the done channel is closed, the phase is finished.
            select {
            case <-done:
                return nil
            default:
            }
            // Try to receive a message, but don't block forever.
            select {
            case msg, ok := <-app.msgChan:
                if !ok {
                    return nil
                }
                return msg
            case <-done:
                return nil
            case <-time.After(100 * time.Millisecond):
                // Re-check gen; if changed, stop. Otherwise re-schedule.
                if app.phaseGen != gen {
                    return nil
                }
                return workflowMsgDrainer(app, gen, done)()
            }
        }
    }
    ```

    Add a helper to safely close a possibly-already-closed channel

    ```go
    // safeClose closes ch if it's non-nil and not already closed.
    // Returns true if it actually closed, false otherwise.
    func safeClose(ch chan struct{}) bool {
        if ch == nil {
            return false
        }
        select {
        case <-ch:
            // Already closed
            return false
        default:
            close(ch)
            return true
        }
    }
    ```

    Use `safeClose(app.msgDone)` in `RunPhaseCmd` instead of the inline
    select-close pattern shown above. The helper centralizes the
    double-close protection.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Runner goroutine → drainer | Runner closes `msgDone` after emitting final PhaseResultMsg. Drainer reads done to know when to stop. |
| TUI Update() → drainer | TUI re-arms the drainer after each message. Each drainer invocation captures the current phaseGen. |
| Engine → channelEmitter | Engine emits messages to the channel via the emitter. After done is closed, emits are no-ops (channel is per-phase, will be GC'd). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03-01 | Tampering | msgDone double-close | mitigate | safeClose helper uses select-default to detect already-closed; never panics. |
| T-14-03-02 | Denial of Service | Drainer re-spawns every 100ms | accept | Each drainer invocation is a single tea.Cmd; the cost is one channel select + 100ms sleep. Negligible CPU. |
| T-14-03-03 | Race Condition | Old drainer running while new phase starts | mitigate | phaseGen check at drainer entry; if gen changed, drainer returns nil. Old drainer cannot process new phase's messages. |
| T-14-03-04 | Race Condition | Runner writes to msgCh after done is closed | mitigate | channelEmitter's Emit uses a 500ms timeout select. If the runner is in the process of writing when done closes, the write may still succeed — but the next drainer invocation will see done-closed and return nil. |
| T-14-03-05 | Information Disclosure | Engine messages in channel | accept | Messages are workflow progress; not sensitive. |
| T-14-03-06 | Tampering | channelEmitter write race with close | mitigate | Go's channel semantics guarantee that a write to an unclosed channel after close panics. The runner uses `defer close(doneCh)` AFTER all writes are done, so the engine's emit-after-runner-return case is the only risk. The 500ms timeout in Emit bounds this. |
</threat_model>
