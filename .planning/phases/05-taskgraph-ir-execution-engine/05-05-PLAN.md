    Add Resume capability to Runner per CONTEXT.md D-17, D-18 and RESEARCH.md.

    1. Add Resume(ctx context.Context, runID uuid.UUID, executeFunc ExecuteFunc) error method:
       - Load TaskGraphExecutionProjection from EventStore (via EventStore.GetProjection("taskgraph_execution"))
       - Get state for runID: proj.GetTaskGraphExecutionState(runID)
       - If no state: return error (no such run)
       - Reconstruct Runner state:
         * r.tasks = state.TaskGraphIR.Tasks
         * r.status = state.TaskStates (map taskID -> ExecutionState)
         * r.retryCounts = state.RetryCounts
         * r.repairCounts = state.RepairCounts
         * r.currentWave = state.CurrentWave
         * Rebuild idToIdx from tasks
       - Replay events since last projection checkpoint:
         * Query EventStore for events with RunID=runID, Seq > projection.LastCheckpointSeq
         * For each event: call projection.Apply(event) to update state
         * Also update Runner's in-memory state to match
       - Resume execution from currentWave:
         * For waveIndex := currentWave; waveIndex < len(ir.Waves); waveIndex++:
           - Same logic as Execute() wave loop (checkpoint gate, ExecuteGroup, failure handling)
         * Note: tasks already in terminal state (COMPLETED/FAILED/SKIPPED) are skipped by ExecuteGroup pre-filter
         * Tasks in RUNNING/WAITING/VERIFYING: transition to WAITING (they were interrupted), then re-execute

    2. Add LastCheckpointSeq to TaskGraphExecutionState to track replay position.

    3. Ensure transitionTask() emits events for ALL transitions (already done in Plan 05-03).

    4. Config: checkpoint_interval from config.Execution.CheckpointInterval (default 100) controls projection checkpoint frequency.

    5. Add RunnerOption WithResume(runID uuid.UUID) to create Runner in resume mode.

    6. Handle edge case: if crash happened during checkpoint gate approval, the checkpoint event may not exist. Projection shows checkpoint as pending. Resume should re-request approval.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-17 | Tampering | Checkpoint data corruption | medium | mitigate | Checkpoint JSON validated on Restore; version field for schema migration |
| T-05-18 | DoS | Unbounded event replay | low | mitigate | Checkpoint interval bounds replay window (default 100 events) |
