    2. Define FailureContext struct: Error string, TaskID int, AttemptNumber int, TaskSnapshot types.TaskIR (for REPAIR prompt context)

    3. RETRY strategy (handleRetry):
       - Check task.RetryCount < r.MaxRetries (from Runner config)
       - Increment task.RetryCount++
       - Call r.transitionTask(taskID, types.ExecutionStateReady)
       - Emit EventTaskRetried with TaskRetriedPayload: TaskID, RetryCount, RunID, FailureError
       - Return error if max retries exceeded (ErrMaxRetriesExceeded)

    4. REPAIR strategy (handleRepair) per D-11:
       - Check task.RepairCount < r.MaxRepairs (new config, default 1)
       - Get provider via r.ProviderRegistry.GetProviderForRequest() with empty ChatRequest, fallback config from r.ProviderConfig
       - If no provider: return ErrNoProviderForRepair
       - Build repair prompt using buildRepairPrompt(task, failure) — include task.Description, Action, Files, failure.Error, AcceptanceCriteria
       - Call provider.ChatCompletion with model from r.ProviderConfig.Default
       - Extract patch from response (extractPatch helper — look for ```diff or unified diff format)
       - Apply patch via r.ToolsDispatcher.Execute(ctx, types.ToolInput{Name: "edit_file", Params: map[string]any{"path": task.Files[0], "patch": patch}})
       - If tool returns error: return wrapped error
       - Increment task.RepairCount++
       - Transition to READY for retry: r.transitionTask(taskID, types.ExecutionStateReady)
       - Emit EventTaskRepaired with TaskRepairedPayload: TaskID, RepairCount, RunID, PatchApplied bool
       - Return error if max repairs exceeded (ErrMaxRepairsExceeded)

    5. REPLAN strategy (handleReplan) per D-12:
       - Emit EventTaskReplanned with ReplanRequestedPayload: FailedTaskID, RunID, FailureError, FailureContext
       - Return nil (Runner will handle IR swap via event subscription)

    6. ESCALATE strategy (handleEscalate) per D-12:
       - Emit EventTaskEscalated with EscalationRequestedPayload: TaskID, RunID, FailureError, Options: []RecoveryAction{RETRY, REPAIR, REPLAN}
       - Block on escalation channel (similar to checkpoint gate) — add EscalationCh to Runner
       - Wait for human decision (RecoveryAction) from TUI S16
       - On decision: set task.RecoveryAction = decision, transition to READY if RETRY/REPAIR, or handle REPLAN
       - Return error on context cancellation (ErrCheckpointTimeout)

    7. Dispatcher method on Runner: handleFailure(ctx, taskID, task, failure FailureContext) error:
       - Read task.RecoveryAction
       - Switch on action: call handleRetry, handleRepair, handleReplan, handleEscalate
       - Default: return ErrInvalidTransition

    8. Helper functions: buildRepairPrompt, extractPatch (simple string extraction between ```diff and ``` or unified diff header)

    Follow error wrapping pattern from internal/core/errors/errors.go (Wrap/Wrapf).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM provider → REPAIR patch | LLM output is untrusted; patch validated by FileEdit tool (Phase 7) before apply |
| Human decision → ESCALATE | Human input via TUI is trusted for approval; correlation ID prevents spoofing |
| Tools dispatcher → FileEdit | Dispatcher enforces permissions, path validation (Phase 7 TOOLS-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Tampering | REPAIR patch injection | high | mitigate | Patch applied via FileEdit tool (not raw write); dispatcher validates path, permissions |
| T-05-06 | DoS | Infinite REPAIR loop | medium | mitigate | MaxRepairs config (default 1) separate from MaxRetries; repair_count tracked per task |
| T-05-07 | Spoofing | Fake escalation decision | medium | mitigate | EscalationCh per-run; correlation via RunID in event; TUI sends decision with RunID |
| T-05-08 | Tampering | Replan event injection | low | mitigate | ReplanRequested event includes failure context; only Runner emits; Planner (Phase 6) consumes |

</threat_model>
