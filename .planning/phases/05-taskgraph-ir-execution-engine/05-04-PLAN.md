  <action>
    Finalize checkpoint.go per RESEARCH.md Pattern 3 and PATTERNS.md, fixing the correlation ID issue (Pitfall 3).

    1. CheckpointGate struct:
       - EventStore *eventstore.SQLiteEventStore
       - approveCh map[string]chan CheckpointApproval (map by CheckpointID for correlation)
       - mu sync.Mutex (protects approveCh map)

    2. RequestApproval(ctx, cp types.Checkpoint, runID uuid.UUID) (CheckpointApproval, error):
       - Emit CheckpointRequested event to EventStore (per D-16)
       - Create or get channel for cp.ID: g.mu.Lock(); ch, ok := g.approveCh[cp.ID]; if !ok { ch = make(chan CheckpointApproval, 1); g.approveCh[cp.ID] = ch }; g.mu.Unlock()
       - Select on ch (with ctx.Done()):
         * On approval: verify approval.CheckpointID == cp.ID (correlation check)
         * Emit CheckpointResolved event (Approved=true) with EvidenceRefs
         * Clean up channel: g.mu.Lock(); delete(g.approveCh, cp.ID); g.mu.Unlock()
         * Return approval
         * On ctx.Done(): emit CheckpointResolved (Approved=false, Reason=ctx.Err()), clean up, return error

    3. SubmitApproval(approval CheckpointApproval) bool:
       - g.mu.Lock(); ch, ok := g.approveCh[approval.CheckpointID]; g.mu.Unlock()
       - If ok: select { case ch <- approval: return true; default: return false }
       - Else: return false (no pending request for this ID)

    4. CheckpointApproval struct: CheckpointID, Approved bool, Approver string, EvidenceRefs []string

    5. CheckpointResolvedPayload in types/event.go already has CheckpointID, Approved, Approver, EvidenceRefs, Reason* — use that.

    6. Ensure CheckpointRequestedPayload has Checkpoint and RunID.

    Note: Runner creates CheckpointGate in New() with its EventStore and passes it to Execute. TUI calls SubmitApproval when user clicks approve/deny on S13.
  </action>

  </verify>
