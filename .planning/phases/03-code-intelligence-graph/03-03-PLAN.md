CallerInfo struct: File string, Line int, Symbol string, Category RiskCategory

ImpactResult struct: Symbol string, DirectCallers []CallerInfo, Indirect []string, AffectedTests []string, Risk RiskCategory

AnalyzeImpact(graph *CodeGraph, index *SymbolIndex, symbol string, depth int) *ImpactResult:
1. Determine symbol's own risk category:
   - Find symbol in index via Define(symbol)
   - If any definition has Exported == true, Risk = RiskAPI
   - If symbol is only in test files (paths ending in _test.go), Risk = RiskTest
   - Otherwise, Risk = RiskRuntime

2. Find direct callers:
   - graph.Callers(symbol) returns []CallEdge
   - For each CallEdge, create CallerInfo with File = edge.CallerFile, Line = edge.CallerLine, Symbol = edge.CallerName
   - Categorize each caller: if caller file is _test.go -> RiskTest, if caller is exported -> RiskAPI, else RiskRuntime

3. Find indirect dependents (transitive):
   - For each direct caller, use graph.Downstream(callerFile, depth) to find transitive dependents
   - Collect unique file paths
   - Filter out the symbol's own file

4. Find affected tests:
   - For each file in DirectCallers + Indirect, check if any test file imports it
   - Use graph.Downstream on each caller file with unlimited depth, filter for _test.go suffix
   - Also check if symbol's definition file has corresponding _test.go file

5. Return ImpactResult with all fields populated

CategorizeSymbolRisk(index *SymbolIndex, symbol string) RiskCategory — helper that determines if a symbol is API, runtime, or test based on its definition locations.

WatcherEvent struct: Path string, EventType WatcherEventType, Timestamp time.Time

FileWatcher struct: watcher *fsnotify.Watcher, ctx context.Context, cancel context.CancelFunc, events chan WatcherEvent, debounce *time.Timer, mu sync.Mutex, workDir string, logger *slog.Logger, parsers []Parser

NewFileWatcher(workDir string, parsers []Parser, logger *slog.Logger) (*FileWatcher, error):
1. fsnotify.NewWatcher()
2. Add workDir and all immediate subdirectories to watcher
3. Return configured FileWatcher

Start(ctx context.Context):
1. Launch goroutine that reads from watcher.Events and watcher.Errors
2. On Create/Write/Remove events: call debounceEvent()
3. On errors: log and continue

debounceEvent():
1. Lock, stop existing debounce timer if any
2. Set new timer with 500ms delay (per D-08)
3. On timer fire: send WatcherEvent to events channel

Events() <-chan WatcherEvent — returns read-only channel

Stop():
1. Cancel context
2. Close fsnotify watcher
3. Close events channel

AddDirectory(path string) error — adds directory to watch
RemoveDirectory(path string) error — removes directory from watch

NewIndexerWithWatcher(workDir string, store types.EventStore, logger *slog.Logger) (*Indexer, error):
1. Create Indexer via NewIndexerWithStore(workDir, store)
2. Create FileWatcher via NewFileWatcher(workDir, parsers, logger)
3. Store watcher in Indexer
4. Return Indexer (watcher not started yet — caller decides when to start)

StartWatching(ctx context.Context):
1. Create child context from ctx: watchCtx, cancel := context.WithCancel(ctx)
2. idx.watchCtx = watchCtx
3. idx.watcher.Start(watchCtx)
4. Launch goroutine that reads from watcher.Events():
   - For each event, call idx.handleWatchEvent(event)

handleWatchEvent(event WatcherEvent):
1. Lock Indexer mutex
2. Based on event type:
   - WatcherModified: add event.Path to changed files list
   - WatcherDeleted: call idx.graph.RemoveNode(relPath), idx.index.RemoveFile(relPath)
   - WatcherCreated: parse the new file, add to graph and index
3. If store is not nil, emit appropriate events (FileDeleted, FileIndexed, SymbolDefined)
4. Update scorer: idx.scorer = NewRelevanceScorer(idx.graph, idx.index)
5. Save cache

StopWatching():
1. If watchCtx != nil, cancel it
2. If watcher != nil, call watcher.Stop()

BuildIncremental(ctx context.Context) error:
1. This is the public method that triggers an incremental rebuild
2. Calls buildIncremental(ctx) (existing method)
3. Returns error

The existing Build(ctx) method remains unchanged — it does full rebuild. BuildIncremental is for --incremental flag. The watcher goroutine calls handleWatchEvent which does incremental updates without going through BuildIncremental.
