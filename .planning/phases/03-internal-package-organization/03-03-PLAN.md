  <action>
    Update all import paths across the codebase. goimports handles automatic resolution — the executor does NOT need manual sed replacements for each subpackage. The approach:

    1. Run `goimports -w .` — this automatically resolves import paths for all moved packages. goimports reads the go.mod module path and the new directory structure to generate correct imports.

    2. If goimports misses any paths (e.g., in non-Go files or string literals), fix them manually with targeted sed:
       - Only apply sed to files that still reference old paths (verified by grep)
       - Pattern: `github.com/eshanized/M31A/internal/tools` → specific subpackage (only where the consuming file actually uses types from that subpackage)
       - Pattern: `github.com/eshanized/M31A/internal/ui/tui` → `github.com/eshanized/M31A/internal/ui/tui/core` (only for files using AppState/lifecycle types)

    3. Key import mappings the executor MUST know:
       - Files using `tools.NewGit()` → import `internal/tools/git`
       - Files using `tools.NewTodo()` → import `internal/tools/todo`
       - Files using `tools.NewCodeComplexity()` → import `internal/tools/codeanalysis`
       - Files using `tools.NewDNSCache()` or `tools.NewHTTPCheck()` → import `internal/tools/network`
       - Files using `AppState` or lifecycle methods → import `internal/ui/tui/core`
       - Files using handler types → import `internal/ui/tui/handlers`
       - Files using screen models → import `internal/ui/tui/screens/<name>`
       - Files using repl types → import `internal/ui/tui/screens/repl`

    4. Run `go build ./...` to verify all imports resolve correctly.

    5. Run `go vet ./...` to catch any remaining issues.
  </action>
  <verify>
    <automated>go build ./... && go vet ./... && ! grep -r 'github.com/eshanized/M31A/internal/tools"' --include='*.go' . | grep -v '_test.go' | grep -v 'tools_reexport'</automated>
  </verify>

    - No stale import paths remain (grep confirms)

  </acceptance_criteria>

  <action>
    Per D-13: "Unit tests that need unexported access stay with source; integration/e2e tests move to tests/."

    STEP 1 — Analyze each test file for unexported access:
    For every *_test.go file in the tools/ and tui/ subdirectories (created by Plan 01 and 02), check whether it references unexported identifiers:
    - Grep for unexported function calls: identifiers starting with lowercase that are not standard library or imported package functions
    - Grep for unexported struct field access: accessing lowercase fields on types
    - Grep for package-level unexported vars/consts: references to lowercase package-level symbols
    - Check if the test uses `package <same>` (white-box) vs `package <same>_test` (black-box) declaration

    Classification rules:
    - WHITE-BOX test (package same, accesses unexported) → STAYS with source, do NOT move
    - BLACK-BOX test (package same_test, uses only exported API) → MOVE to tests/ directory
    - INTEGRATION/E2E test (imports test binaries, uses external processes) → MOVE to tests/ directory
    - Test that references only exported types/functions from its own package → MOVE to tests/ directory

    STEP 2 — Move eligible tests to tests/ directory:
    Create directory structure:
    - internal/tests/tools/git/
    - internal/tests/tools/todo/
    - internal/tests/tools/codeanalysis/
    - internal/tests/tools/network/
    - internal/tests/tui/core/
    - internal/tests/tui/handlers/
    - internal/tests/tui/input/
    - internal/tests/tui/update/
    - internal/tests/tui/routing/

    Move only the tests classified as MOVE in Step 1. Leave white-box/unexported-access tests with their source files.

    For moved test files:
    - Update package declaration to match the tests/ directory (e.g., `package git` for tests/tools/git/)
    - Update imports to reference the source package by its new import path
    - Run `goimports -w .` to fix import paths

    STEP 3 — Verify:
    Run `go test ./...` to confirm:
    - Tests that stayed with source still compile and pass (they retain unexported access)
    - Tests moved to tests/ compile and pass (they use only exported API)
    - No test failures
  </action>
  <verify>
    <automated>go test ./internal/tools/... ./internal/ui/tui/... ./internal/tests/... 2>&1 | tail -20</automated>
  </verify>

    - Black-box and integration tests are in tests/ directory
    - tests/ directory mirrors source structure per D-12
    - All tests pass with `go test ./...`
    - No compilation errors from moved tests
  </acceptance_criteria>
  <done>
