<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI pipeline -> GitHub Issues | Auto-filed crash issues must not leak secrets or internal paths |
| Panic handler -> file system | Crash reports written to user home directory must not overwrite existing data |
| stderr output -> CI logs | Crash output to stderr must not contain API keys or secrets |
| Benchstat JSON -> GitHub Pages | Dashboard must not expose sensitive benchmark data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Denial of Service | Panic handler | high | mitigate | RecoverAndCapture re-panics after capture to preserve exit behavior; no infinite loop risk |
| T-07-02 | Information Disclosure | Crash reports | medium | mitigate | Crash reports contain only version/OS/stack — no API keys, no file contents. Stderr output is same. |
| T-07-03 | Tampering | CI auto-filed issues | low | accept | Issues filed via gh CLI with GITHUB_TOKEN; only CI can file, not external users |
| T-07-04 | Elevation of Privilege | Crash file writes | low | accept | Written to ~/.m31a/crashes/ (user-owned directory); no privilege escalation path |
| T-07-09 | Information Disclosure | Crash report file permissions | medium | mitigate | Crash files created with 0600 permissions (owner-only read/write); umask applied to prevent world-readable files |
</threat_model>
