<objective>
Fix audit finding **C-1** (CRITICAL — TUI panic on nil `m.replModel`).
Multiple branches of `AppState.Update()` dereference `m.replModel` (calling
`m.replModel.SetX(...)` or reading `m.replModel.streamContent` /
`m.replModel.streamCh` / `m.replModel.activeSegmentType`) without a
nil check. The struct is only initialized on two happy paths
(API key present AND provider exists / first-run), so the REPL can be
entered after a config update or first-run exit where `m.replModel` is
still nil for one or more ticks. Any key/msg delivered in that window
panics with a nil-pointer deref.

Add a one-line guard `if m.replModel == nil { return nil, nil }` at the
top of every `Update()` case that touches `m.replModel.*`, and add a
regression test that confirms Update() does not panic when `m.replModel`
is nil and any of the relevant `tea.Msg` types is delivered.

**Output:** Modified `internal/tui/app_update.go` with nil-guards; new
`internal/tui/app_update_nilsafety_test.go` with
`TestApp_Update_ReplModelNil_NoPanic`.
</objective>
