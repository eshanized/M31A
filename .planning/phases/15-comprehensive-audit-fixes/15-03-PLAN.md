<objective>
Fix three LLM input/output handling findings:

- **C-4 (CRITICAL)** — `parseToolCalls` in `internal/workflow/engine.go`
  walks the entire LLM response without a length cap and runs
  `extractJSONObject` (which uses bracket-depth tracking with no
  boundary check) at every `{` position. A 10 MB LLM reply with
  100k `{` characters causes ~5 GB of byte-slicing work — OOM.
- **H-5 (HIGH)** — `extractJSONObject` does not strip `//` or `/* */`
  comments from the JSON the LLM emits. When the model includes
  comments as "hints", `json.Unmarshal` rejects the blob and the
  retry loop in `runPlan` wastes an attempt on the same parse error.
- **M-22 (MEDIUM)** — The `case "done":` branch in
  `repl_stream.go:62` is empty; `streaming.go` sets
  `lastUsage = &types.Usage{}` (an **empty** usage) and
  `StreamDoneMsg{Usage: lastUsage}` carries zeros, so cost
  calculations produce `$0.00` always. The provider SSE parser
  never reads the `usage` chunk.

**Output:** New `ErrToolInputTooLarge` sentinel; capped
`parseToolCalls` with input-size and tool-count limits; comment
stripping in `extractJSONObject`; SSE usage chunk parsed and
propagated through `StreamDoneMsg.Usage`; regression tests for
each fix.
</objective>
