<objective>
Fix audit findings **C-5, C-6, C-7 (CRITICAL) and M-1, M-2 (Medium)** in
the tool security surface.

- **C-5** — Bash timeout validation is unsafe. The current code
  (`internal/tools/bash.go` lines 54-56) silently rewrites a non-positive
  timeout to 1800s with no upper bound. A typo'd `timeout: 99999999`
  would let a runaway process hold the TUI for ~3 years.
- **C-6** — Bash tool has no hard output cap. Output is streamed line by
  line to the tool card; a misbehaving command (`yes`, `cat /dev/urandom`)
  can grow memory unboundedly. The `BashOutputLimit` constant
  (`internal/types/constants.go:14`) exists but is unused.
- **C-7** — WebFetch SSRF protection uses `fmt.Errorf` (untyped). The
  `isPrivateIP()` check at `internal/tools/webfetch.go:67` cannot be
  detected by `errors.Is` in callers, and the IPv6 path is missing the
  ULA/link-local ranges (fc00::/7 and fe80::/10).
- **M-1** — `Dispatcher.Execute` for `Dangerous`/`Destructive` tools
  returns a generic error string. Callers cannot programmatically
  distinguish "user denied" from "tool crashed" without string parsing.
- **M-2** — Bash tool input validation: when LLM emits `command: 12345`
  (a number, not a string), the code path returns
  `fmt.Errorf("parameter command must be a string")` — no typed
  sentinel.

**Output:** Two new typed sentinels in `internal/errors/errors.go`,
hardening in `internal/tools/bash.go`, typed SSRF error in
`internal/tools/webfetch.go`, typed permission error in
`internal/tools/dispatcher.go`, and 3 new test files with regression
suites. All 5 findings have typed-error coverage and a passing test.
</objective>

    Apply three changes to `internal/tools/bash.go`:

    **1. Validate `command` is a string (M-2)**
    Replace the current `params["command"].(string)` panic-prone cast
    with an explicit type switch. If the value is missing OR is not a
    string, return:
    ```go
    return types.ToolResult{}, fmt.Errorf("parameter command must be a string: %w", m31errors.ErrToolExecution)
    ```
    Use the same wrap pattern in the rest of the file (search for
    `fmt.Errorf(.*%w.*Err`).

    **2. Validate `timeout` (C-5)**
    Replace the current `if timeoutSec <= 0 { timeoutSec = 1800 }`
    block with:
    - If `timeoutSec <= 0`: return
      `fmt.Errorf("timeout must be positive: %w", m31errors.ErrInvalidTimeout)`
    - If `timeoutSec > int(m31types.BashTimeout.Seconds())`: return
      `fmt.Errorf("timeout exceeds max %s: %w", m31types.BashTimeout, m31errors.ErrInvalidTimeout)`
    - Else: use the value as-is. Do NOT silently rewrite it.

    **3. Add hard output cap (C-6)**
    Wrap the `cmd.Stdout` and `cmd.Stderr` writers in a
    `limitWriter` that drops bytes beyond `m31types.BashOutputLimit`
    and counts the dropped bytes. The streaming loop in Execute()
    should track total bytes emitted; if a single line exceeds the
    cap, the line is truncated to `BashOutputLimit` and a trailing
    marker `[... N bytes truncated]` is appended. Total memory per
    Bash invocation is bounded by `BashOutputLimit`.

    Implementation notes for limitWriter:
    - Implement `io.Writer` (Write method)
    - On overflow, the writer stops accepting bytes (Write returns
      len(p), nil) but increments a `dropped` counter
    - The streaming goroutine checks `dropped > 0` and emits a
      one-time `[... N bytes truncated by output cap]` message via
      the existing output channel

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM tool call → Bash tool | LLM-emitted tool params cross into Go's `params map[string]any` here. Type assertion errors must not panic, and bad inputs must be rejected with typed errors. |
| LLM tool call → WebFetch URL | LLM-emitted URLs cross into the network stack. Private IPs must be blocked at this boundary. |
| Permission gate → user | The user must explicitly approve Dangerous/Destructive tools. The denial path must be observable via typed errors. |

| Threat ID | Category | Component | Disposition | Mitigation |

| T-15-04-02 | Denial of Service | Bash tool with `yes | head -n 1000000` | mitigate | C-6: limitWriter on stdout/stderr, total output bounded at `BashOutputLimit` |
