# Plan 29-03: Streaming Pipeline

## Objective

Implement the streaming pipeline that connects provider LLM responses to the TUI. The pipeline uses a goroutine that owns the channel lifecycle, with the TUI holding a read-only reference.

## must_haves

- StartStreamCmd creates goroutine that reads StreamIterator and emits StreamMsg/StreamDoneMsg/StreamErrorMsg
- Stream listener polls channel and emits messages to Update()
- Channel lifecycle owned by goroutine creator
- Cancellation support via context
- channelCloser for exactly-once close semantics
- channelEmitter implements workflow.MsgEmitter

## Tasks

### Task 1: Create app_channel.go

<read_first>
- internal/workflow/engine.go — MsgEmitter interface
- bubbletea — tea.Cmd, tea.Msg
</read_first>

<action>
Create internal/tui/app_channel.go:

1. channelCloser struct:
   { ch chan struct{}, once sync.Once }
   - Close() — calls once.Do(close(ch))
   - Safe against double-close

2. newChannelCloser() *channelCloser

3. channelEmitter struct:
   { ch chan tea.Msg, timeout time.Duration }
   - Implements workflow.MsgEmitter interface
   - Emit(msg tea.Msg) — sends msg to channel with timeout (default 500ms)
   - If channel full after timeout, drops message (safety valve)

4. newChannelEmitter(ch chan tea.Msg) *channelEmitter
</action>

<acceptance_criteria>
- channelCloser.Close() can be called multiple times without panic
- channelEmitter.Emit() sends message to channel
- channelEmitter.Emit() does not block longer than timeout
- channelEmitter implements workflow.MsgEmitter interface
</acceptance_criteria>

### Task 2: Create streaming.go

<read_first>
- internal/types/types.go — StreamChunk, StreamIterator, StreamChunkMsg
- internal/tui/types.go (from Plan 29-01) — StreamMsg, StreamDoneMsg, StreamErrorMsg
- internal/tui/constants.go
- bubbletea — tea.Cmd, tea.Msg, tea.Batch
</read_first>

<action>
Create internal/tui/streaming.go:

1. StartStreamCmd(iter *types.StreamIterator, source string) (tea.Cmd, chan struct{})
   - Creates channelCloser for lifecycle
   - Returns tea.Cmd that:
     a. Spawns goroutine
     b. Goroutine reads iter.Next() in loop
     c. For each chunk: sends StreamMsg{Chunk, Source} to channel
     d. On iter.Next() error: sends StreamErrorMsg{Source, Err}
     e. On iter.Next() nil (done): sends StreamDoneMsg{Source, Usage}
     f. Calls iter.Close()
     g. Calls closer.Close()
   - Returns the channel for listener to poll

2. StreamListenerCmd(ch <-chan tea.Msg, closer *channelCloser) tea.Cmd
   - Returns tea.Cmd that:
     a. Non-blocking read from channel
     b. If message available: returns it
     c. If channel closed: returns nil (stops polling)
     d. Otherwise: returns tea.Cmd that re-polls after small delay

3. MakeStreamCancelFunc() (context.CancelFunc, <-chan struct{})
   - Creates context with cancel
   - Returns cancel func and done channel

4. StreamSource constants:
   StreamSourceREPL = "repl"
   StreamSourceDiscuss = "discuss"
   StreamSourcePlan = "plan"
   StreamSourceExecute = "execute"
   StreamSourceVerify = "verify"
</action>

<acceptance_criteria>
- StartStreamCmd returns channel and cmd
- Goroutine reads all chunks from iterator
- StreamMsg sent for each content/thinking chunk
- StreamDoneMsg sent with usage on completion
- StreamErrorMsg sent on error
- iter.Close() called in all paths (including error)
- channelCloser.Close() called when goroutine exits
- StreamListenerCmd polls channel and emits messages
- StreamListenerCmd stops when channel is closed
- No goroutine leaks (all goroutines exit)
</acceptance_criteria>
