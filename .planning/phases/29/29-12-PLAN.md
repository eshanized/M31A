# Plan 29-12: Workflow Engine Integration

## Objective

Wire the workflow engine to the TUI via the drainer pattern and phase generator.

## Tasks

### Task 1: app_workflow.go

<read_first>
- internal/tui/app_state.go
- internal/tui/types.go
- internal/workflow/engine.go — Engine, NewEngine, PhaseResult
- internal/workflow/engine_messages.go — all tea.Msg types
- internal/tools/dispatcher.go — Dispatcher
- internal/tokens/ — Estimator
- pkg/session/ — Manager
- internal/provider/interface.go — LLMProvider
- internal/config/types.go — Config
- internal/git/git.go — Git
</read_first>

<action>
Create app_workflow.go:

1. initWorkflowEngine() error
   - Create workflow.Engine with all dependencies
   - Set model, provider, git, dispatcher, msgEmitter
   - Start drainer goroutine
   - Store engine in m.workflowEngine

2. startDrainer() chan tea.Msg
   - Create channel
   - Spawn goroutine that:
     a. Reads tea.Msg from engine channel
     b. Wraps in tea.Cmd: func() tea.Msg { return msg }
     c. Sends to Bubble Tea program via m.program.Send()
   - Return stop channel

3. Phase generator closure:
   - Returns PhaseGenerator that maps WorkflowPhase → runPhase
   - Each runPhase calls engine.RunPhase(ctx, phase, goal)
   - Results sent as PhaseSwitchMsg, PlanReadyMsg, TaskStartMsg, etc.

4. startWorkflow(goal string) (tea.Model, tea.Cmd)
   - Create new session if needed
   - Set workflow goal
   - Initialize engine
   - Transition to PhaseInitialize
   - Return command to run first phase

5. cancelWorkflow() (tea.Model, tea.Cmd)
   - Cancel workflow context
   - Return to REPL
   - Show cancellation toast
</action>

<acceptance_criteria>
- initWorkflowEngine creates engine with all deps
- Drainer goroutine reads and dispatches messages
- Phase generator maps all 6 phases
- startWorkflow begins workflow
- cancelWorkflow stops workflow gracefully
- No goroutine leaks
- No channel panics
</acceptance_criteria>
