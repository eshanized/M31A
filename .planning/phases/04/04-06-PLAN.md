<action>
Create `internal/tools/dispatcher.go`:

```go
package tools

import (
    "context"
    "fmt"
    "sync"
    "time"

    m31errors "github.com/eshanized/M31A/internal/errors"
    "github.com/eshanized/M31A/internal/types"
)

type Dispatcher struct {
    mu          sync.RWMutex
    tools       map[string]types.Tool
    permissions map[string]bool       // remembered permissions (tool name → allowed)
    gate        PermissionGate         // nil for Safe/Medium only; set for Dangerous/Destructive
    requestCh   chan PermissionRequest // channel for permission requests
    responseCh  chan PermissionResponse // channel for permission responses
}

func NewDispatcher() *Dispatcher

func (d *Dispatcher) Register(tool types.Tool)

func (d *Dispatcher) Execute(ctx context.Context, call types.ToolCall) (types.ToolResult, error)

func (d *Dispatcher) ApprovePermission(allowed bool, remember bool)

func (d *Dispatcher) List() []string

func (d *Dispatcher) GetTool(name string) (types.Tool, bool)
```

**`Register(tool types.Tool)`:**
- Add tool to `d.tools` map keyed by `tool.Name()`
- Panic on duplicate registration (programming error)
- Thread-safe: write lock

**`Execute(ctx, call)`:**
1. Look up tool by `call.Name` — return `m31errors.ErrToolExecution` with "unknown tool: <name>" if not found
2. Parse `call.Input` (json.RawMessage) into `ToolInput{Name: call.Name, Params: map[string]any}`
3. Check tool's `RiskLevel()`:
   - **Safe / Medium:** execute immediately
   - **Dangerous / Destructive:**
     a. Check remembered permissions (thread-safe read from `d.permissions`) — if previously allowed with `remember=true`, execute
     b. Otherwise, create `PermissionRequest{ToolName: call.Name, RiskLevel: tool.RiskLevel(), TimeoutSecs: 300}`
     c. Send to `d.requestCh` (non-blocking send with select/default — if channel is full, block)
     d. Wait for response on `d.responseCh` (with select and ctx.Done)
     e. If `resp.Remember == true`, store in `d.permissions[tool.Name()] = resp.Allowed`
     f. If `resp.Allowed == false`, return `m31errors.ErrPermissionDenied`
4. Call `tool.Execute(ctx, input)` with a 5-minute timeout for the permission window
5. Wrap result, return `ToolResult{ToolCallID: call.ID, Output: result.Output, Error: errStr, DurationMs: elapsed, Truncated: result.Truncated}`

**`ApprovePermission(allowed, remember)`:**
- Send `PermissionResponse{Allowed: allowed, Remember: remember}` to `d.responseCh`
- Used by TUI integration when user responds to modal

**`List()`:**
- Return sorted list of registered tool names

**`GetTool(name)`:**
- Return tool from map, with `ok` bool

**Permission channels:**
- `requestCh` is a buffered channel (buffer size 1) — only one permission request at a time
- `responseCh` is an unbuffered channel — single response expected
- Initialize both in `NewDispatcher()`

**Remember flag semantics:**
- If user selects "Remember" in the permission modal, `remember=true`
- Stored permissions persist for the lifetime of the Dispatcher (one session)
- No persistence to disk in V1
</action>

**Step 2a: Permission listener goroutine**

Start a goroutine during app initialization that bridges the dispatcher's synchronous permission request with Bubble Tea's async message loop:

```go
// In NewApp() or app initialization:
go func() {
    for req := range d.Dispatcher.RequestCh() {
        // When dispatcher needs permission, send to Bubble Tea update loop
        app.Update(PermissionRequestMsg{Request: req})
        // Wait blocks until TUI responds — handled by AppState internals
    }
}()
```

**Implementation note:** The dispatcher's `Execute()` method blocks when it sends a `PermissionRequest`, waiting for a `PermissionResponse` on the response channel. The goroutine above receives from `requestCh` and dispatches to the TUI. The TUI's `Update()` captures the user's Y/N/A keypress, creates `PermissionResponseMsg`, which triggers `AppState.Update()` to call `d.Dispatcher.ApprovePermission()`, which sends the response back, unblocking `Execute()`.

**Step 3: Wire ToolCall dispatch in the streaming pipeline**

In the streaming pipeline (likely in `internal/tui/repl.go` or wherever `handleStreamDoneMsg` lives):

1. Read the existing `handleStreamDoneMsg` function that receives `StreamDoneMsg` containing `ToolCalls []types.ToolCall`
2. For each `ToolCall` in the message:
   a. Call `dispatcher.Execute(ctx, toolCall)` 
   b. If error: create a tool card showing the error
   c. If success: create a `ToolCard` from the result using existing `NewToolCard()` component
   d. Append the card to the conversation view (tool cards list)
   e. Create a new `Message` with role `"tool"` containing the serialized result (this goes back to LLM as context)
   f. Replace `getToolCallsFromSegments()` stub with actual tool call parsing from segments
3. After all tool calls are dispatched:
   - Re-invoke the LLM with the conversation including tool results
   - The LLM receives the tool results and can decide next action (more tool calls or final response)

**Step 4: Update provider ToolDefinition generation**

In `internal/provider/interface.go` or wherever ToolDefinition is defined:

```go
func ToolsToDefinitions(tools []types.Tool) []ToolDefinition {
    defs := make([]ToolDefinition, 0, len(tools))
    for _, t := range tools {
        defs = append(defs, ToolDefinition{
            Name:        t.Name(),
            Description: t.Description(),
            Parameters:  inferParameters(t),
        })
    }
    return defs
}
```

This enables the provider layer to tell the LLM what tools are available and how to call them. The `inferParameters` function can be a simple map based on known tool names.
