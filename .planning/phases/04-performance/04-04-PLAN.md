# 04-04: Shared Dev Server Buffer Pool

## Goal

Replace per-server 256KB ring buffer allocation with a shared `sync.Pool` and enforce a global memory cap to prevent unbounded memory growth when multiple dev servers run simultaneously.

## Locked Decisions

- D-07: Shared dev server buffer pool with total memory limit
- D-08: Measure with -memprofile first, then optimize

## Tasks

### Task 1: Implement shared buffer pool with memory cap

<read_first>
- internal/tools/exec/devserver.go:21-68
- internal/tools/exec/devserver.go:179-247 (startServer)
</read_first>

<action>
In `internal/tools/exec/devserver.go`:

1. Add a shared buffer pool with global memory tracking:
```go
var (
    devServerBufferPool = sync.Pool{
        New: func() any {
            if totalDevServerBytes.Load() >= maxTotalDevServerBytes {
                return nil
            }
            totalDevServerBytes.Add(int64(maxLogBytes))
            return NewRingBuffer(maxLogBytes)
        },
    }
    totalDevServerBytes atomic.Int64
    maxTotalDevServerBytes int64 = 4 * 1024 * 1024 // 4MB total cap
)
```

2. Modify `startServer()` to acquire from pool instead of `NewRingBuffer(maxLogBytes)`:
```go
buf := devServerBufferPool.Get().(*ringBuffer)
if buf == nil {
    // Fallback: memory cap reached, allocate smaller buffer
    buf = NewRingBuffer(maxLogBytes / 4)
}
```

3. Modify `stopByID()` to return buffer to pool when server stops:
```go
devServerBufferPool.Put(entry.logs)
totalDevServerBytes.Add(-int64(maxLogBytes))
```

4. Add a `Reset()` method to `ringBuffer` to clear content before returning to pool:
```go
func (rb *ringBuffer) Reset() {
    rb.mu.Lock()
    defer rb.mu.Unlock()
    rb.buf = rb.buf[:0]
    rb.lines = 0
}
```

5. Call `rb.Reset()` before `devServerBufferPool.Put(entry.logs)` to prevent stale data leakage.
</action>

<acceptance_criteria>
- `devServerBufferPool` declared and used in `startServer()`
- `stopByID()` returns buffer to pool after `Reset()`
- `totalDevServerBytes` tracked via `atomic.Int64`
- Pool returns `nil` when memory cap is reached, forcing fallback
- Existing devserver tests pass
- `go vet ./internal/tools/exec/...` passes
</acceptance_criteria>
