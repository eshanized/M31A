# 04-03: Rate Limiter Refactor

## Goal

Replace the channel-based token bucket rate limiter (two goroutines + tickers) with `golang.org/x/time/rate` for zero-goroutine rate limiting, reducing scheduling overhead under high tool concurrency.

## Locked Decisions

- D-10: Semaphore-based concurrency control (already implemented, unchanged)

### Task 2: Replace channel-based rate limiter with rate.Limiter

<read_first>
- internal/tools/dispatcher.go:24-159
- internal/tools/dispatcher.go:231-248 (Execute method rate limit section)
</read_first>

<action>
In `internal/tools/dispatcher.go`:

1. Replace the rate limiter fields:
   - Remove: `rateTokens chan struct{}`, `rateTicker *time.Ticker`, `rateDone chan struct{}`
   - Remove: `dangerousRateTokens chan struct{}`, `dangerousRateTicker *time.Ticker`, `dangerousRateDone chan struct{}`
   - Add: `rateLimiter *rate.Limiter`, `dangerousLimiter *rate.Limiter`

2. In `newDispatcher()`:
   - Create limiters: `rate.NewLimiter(rate.Limit(ToolRateLimitPerSec), ToolRateLimitBurst)`
   - Create dangerous limiter: `rate.NewLimiter(rate.Limit(DangerousRateLimitPerSec), DangerousRateLimitBurst)`
   - Remove goroutine spawning and channel initialization

3. In `Execute()`:
   - Replace `select { case <-d.rateTokens: ... }` with `d.rateLimiter.Wait(ctx)`
   - Replace dangerous token bucket select with `d.dangerousLimiter.Wait(ctx)`
   - Both methods respect context cancellation automatically

4. In `Stop()`:
   - Remove `close(d.rateDone)`, `d.rateTicker.Stop()`, `close(d.dangerousRateDone)`, `d.dangerousRateTicker.Stop()`
   - `rate.Limiter` has no goroutines to stop -- `Stop()` becomes a no-op for rate limiting (keep `drainChannels()` and `stopOnce`)
</action>

<acceptance_criteria>
- `rateLimiter` and `dangerousLimiter` fields replace all channel/ticker/done fields
- `Execute()` calls `rateLimiter.Wait(ctx)` instead of channel receive
- `Stop()` no longer closes rate-related channels or stops tickers
- No goroutines spawned for rate limiting
- Existing dispatcher tests pass with `-race`
- `go vet ./internal/tools/...` passes
</acceptance_criteria>
