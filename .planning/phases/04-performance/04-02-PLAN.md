# 04-02: SSE Buffer Pool

## Goal

Pool 1MB SSE scanner buffers via `sync.Pool` instead of allocating a new buffer per connection, reducing GC pressure and allocation cost.

## Locked Decisions

- D-05: sync.Pool for hot paths (SSE, dispatch, streaming)
- D-06: Pooled SSE buffers via sync.Pool
- D-08: Measure with -memprofile first, then optimize

## Tasks

### Task 1: Add sync.Pool for SSE scanner buffers

<read_first>
- internal/integrations/provider/sse.go:23-51
</read_first>

<action>
In `internal/integrations/provider/sse.go`:

1. Add a package-level `sync.Pool` for `*[]byte` buffers:
```go
var sseBufferPool = sync.Pool{
    New: func() any {
        buf := make([]byte, 0, sseMaxLineLength)
        return &buf
    },
}
```

2. Modify `NewSSEParserWithContext` to acquire buffer from pool instead of allocating:
```go
bufPtr := sseBufferPool.Get().(*[]byte)
scanner := bufio.NewScanner(resp.Body)
scanner.Buffer(*bufPtr, sseMaxLineLength)
```

3. Store `bufPtr` in `SSEParser` struct (new field: `bufPtr *[]byte`).

4. Modify `Close()` to return buffer to pool:
```go
if p.bufPtr != nil {
    sseBufferPool.Put(p.bufPtr)
    p.bufPtr = nil
}
```

Do NOT zero the buffer -- `bufio.Scanner` overwrites as it reads. The buffer size is fixed at `sseMaxLineLength` so stale-data risk is zero.
</action>

<acceptance_criteria>
- `sseBufferPool` is declared and used in `NewSSEParserWithContext`
- `SSEParser.Close()` returns buffer to pool
- No `make([]byte, 0, sseMaxLineLength)` allocation in `NewSSEParserWithContext`
- Existing SSE parser tests pass
- `go vet ./internal/integrations/provider/...` passes
</acceptance_criteria>
