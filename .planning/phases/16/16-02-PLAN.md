## Task 1: Map Common Errors to Human-Readable Messages

**Files Modified:** `internal/tui/app_update.go`, `internal/tui/repl_stream.go`, `internal/errors/errors.go`

<read_first>
- `internal/tui/app_update.go` — line 531 (`fmt.Sprintf("Error: %v", msg.Err)`)
- `internal/tui/repl_stream.go` — lines 179-180 (`fmt.Sprintf("✗ Error: %v", err)`)
- `internal/errors/errors.go` — current sentinel errors
</read_first>

<action>
1. Create a new function `UserMessage(e error) string` in `internal/errors/errors.go`
2. Map common error patterns to user-friendly messages:
   - `connection refused` → "Cannot reach provider — check your internet connection"
   - `context canceled` → "Request cancelled"
   - `401` / `ErrInvalidKey` → "Invalid API key — run /settings to update"
   - `429` / `ErrRateLimited` → "Rate limited — retry in a moment"
   - `503` / `ErrProviderUnreachable` → "Provider temporarily unavailable — try again later"
   - `EOF` / `unexpected end of JSON` → "Connection lost — try again"
3. In `app_update.go`, replace `fmt.Sprintf("Error: %v", msg.Err)` with `errors.UserMessage(msg.Err)`
4. In `repl_stream.go`, replace `fmt.Sprintf("✗ Error: %v", err)` with `errors.UserMessage(err)`
5. For unrecognized errors, fall back to "An error occurred — check logs for details"
</action>

<acceptance_criteria>
- Network errors display human-readable messages instead of Go stack traces
- API key errors suggest running /settings
- Rate limit errors suggest retrying
- `go test ./internal/errors/... -run TestUserMessage` passes
- `go test ./internal/tui/... -run TestErrorDisplay` passes
</acceptance_criteria>
