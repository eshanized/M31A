  <action>
    Create benchmark CI workflow and integrate with CI per RESEARCH.md Code Example (Benchmark CI Job) and D-08:

    1. **.github/workflows/benchmarks.yml** — New workflow file:
       - Triggers: push to master, PR to master, schedule (nightly), workflow_dispatch
       - Job: `benchmark` on ubuntu-latest (30 min timeout)
       - Steps:
         - Checkout with fetch-depth: 0 (needed for baseline comparison)
         - Setup Go 1.25.12 with cache
         - Run benchmarks: `go test -bench=. -benchmem -count=10 -run=^$ ./... > new.txt`
         - Fetch baseline from main: stash, checkout main, run benchmarks → old.txt, restore
         - Install benchstat: `go install golang.org/x/perf/cmd/benchstat@latest`
         - Compare: `benchstat -delta 50% old.txt new.txt | tee benchstat-output.txt`
         - Fail on regression: grep for "p=0.0" in output (benchstat marks significant regressions)
         - Upload artifacts: new.txt, old.txt, benchstat-output.txt
         - If on master branch: commit benchstat-output.txt to gh-pages branch for dashboard
       - Concurrency: cancel in-progress runs for same branch

    2. **.github/workflows/ci.yml** — Extend existing CI:
       - Add `benchmark` job that calls benchmarks.yml via `uses: ./.github/workflows/benchmarks.yml` or duplicate key steps
       - Or add `needs: [lint, test, security, build]` and run benchmark as final gate
       - Ensure benchmark runs on PR and push to master

    3. **Makefile** — Add local benchmark targets:
       - `make bench` — Run benchmarks locally (current)
       - `make bench-compare` — Compare against main branch baseline (requires git)
       - `make bench-install` — Install benchstat
       - Use `go test -bench=. -benchmem -count=10 -run=^$ ./...`

    Per D-08: Benchmark CI job with regression detection (benchstat), 50% threshold.
    Per RESEARCH.md: Benchstat is official Go tool, statistical rigor, CI-integrated.
    Per RESEARCH.md Pitfall 5: Benchstat 50% delta threshold — tune after 2-3 runs if too sensitive/loose.

## Trust Boundaries

| GitHub Actions → Build/Deploy | CI/CD pipelines with write access to repo (gh-pages, releases) |
| Dependabot → Repository | Automated PR creation for dependency updates |
| GoReleaser → Package Registries | Release artifacts published to GitHub Releases |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-14 | Injection | GitHub Actions workflow YAML | low | mitigate | Workflow files in repo, reviewed via PR; no user input in workflow definition |
| T-06-15 | Tampering | Dependabot PRs | medium | mitigate | Require review for Dependabot PRs; auto-merge only for grouped minor/patch |
| T-06-16 | Tampering | Release artifacts | high | mitigate | GoReleaser signs artifacts; verify checksums; publish to GitHub Releases only |
| T-06-17 | DoS | Benchmark CI resource exhaustion | low | mitigate | 30-min timeout; ubuntu-latest runner limits; cancel-in-progress concurrency |
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new package installs; benchstat from official Go module proxy |
</threat_model>
