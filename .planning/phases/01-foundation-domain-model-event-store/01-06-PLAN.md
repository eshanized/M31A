<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| .planning/ files → Migration | Source artifacts are user-controlled; malicious content could exploit parsers |
| Migration → EventStore | Migration writes events; failure mid-migration could leave partial state |
| Migration → Archive | Archives .planning/; rename could fail leaving both directories |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | Malicious .planning/ content | high | mitigate | Parsers treat input as untrusted; validate all parsed data; fail fast on invalid (D-11) |
| T-06-02 | Tampering | Path traversal in planningDir/m31aDir | high | mitigate | Validate both paths with filepath.Clean + EvalSymlinks; ensure planningDir exists, m31aDir under workspace |
| T-06-03 | Information Disclosure | Secrets in .planning/ migrated to events | critical | mitigate | .planning/ has no secrets (verified); config.json has no API keys; keys in env/keychain only |
| T-06-04 | Denial of Service | Partial migration leaves corrupt state | high | mitigate | Migration is event-sourced: MigrationStarted event first; if fails, .m31a/ incomplete — user can retry; MigrationCompleted only on full success |
| T-06-05 | Tampering | Archive rename fails | medium | mitigate | Use os.Rename (atomic on same filesystem); if cross-device, copy + remove with verification |
| T-06-SC | Supply Chain | Standard library only | low | accept | No external deps for migration logic |
</threat_model>
