<objective>
Fix audit findings **H-1, H-2, H-3, H-4, H-6, H-15, H-16, H-17, H-18 (High)
and M-3, M-4, M-5 (Medium)** in the six-phase workflow engine.

- **H-1** — `parseToolCalls` in `internal/workflow/engine.go` returns
  an empty list when the LLM emits malformed JSON. The Execute
  phase then sees "no tool calls" and ends the turn, silently
  dropping the bad response.
- **H-2** — `extractJSONObject` does not strip `// line` or
  `/* block */` comments. Some LLMs (especially reasoning models)
  emit `// fix the bug` comments inline in their JSON output,
  breaking `json.Unmarshal`.
- **H-3** — `TaskRunner.Schedule()` detects cycles but returns a
  string-formatted error. The TUI cannot match
  `errors.Is(err, m31errors.ErrCircularDependency)`.
- **H-4** — Plan phase schema validation does not enforce unique
  task IDs nor check that every `dependencies[]` entry references
  an existing ID. A typo'd dep is silently accepted.
- **H-6** — Phase transition guard is missing. Calling
  `engine.TransitionTo(PhaseExecute)` from `PhaseInitialize` is
  accepted; the engine only logs "skipping Plan".
- **H-15** — Execute phase does not write a checkpoint before each
  task. A heal attempt that corrupts state has no rollback point.
- **H-16** — Ship phase updates `LEDGER.md` with a non-atomic
  write. A crash mid-write corrupts the ledger.
- **H-17** — `Session.Load` does not validate required fields (ID
  is non-empty, StartedAt is non-zero, WorkflowPhase is a known
  value). Corrupt sessions load as zero-value structs.
- **H-18** — Ship phase can overwrite an existing ledger entry for
  the same session ID. The ledger has no idempotency check.
- **M-3** — `parseToolCalls` does not handle the case where the
  LLM returns a single object (not an array) — the parser fails
  on a `{...}`.
- **M-4** — Plan validator does not check for self-referential
  dependencies (task 5 depends on task 5). The cycle detector
  only fires on multi-node cycles.
- **M-5** — `runExecute` increments `toolCallCount` but the
  variable is declared but never read after the loop. Dead
  state.

**Output:** Typed errors in engine + runner, comment stripping in
`extractJSONObject`, schema validation for unique IDs and dep
existence, phase transition guard, pre-task checkpoints, atomic
ledger update, session field validation, ledger idempotency. One
new test file with 8 regression tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM JSON output → parseToolCalls | LLM-emitted JSON crosses into Go's json.Unmarshal. Malformed input must be rejected with typed errors, not silently dropped. |
| Plan validator → task list | The Plan phase produces a task list consumed by Execute. Schema violations must be caught at validation time, not at execution time. |
| Phase engine → UI | Out-of-order phase transitions corrupt the workflow state machine. The guard must reject illegal transitions with a typed error. |
| Execute → disk | Checkpoint before each task protects against heal-induced corruption. Atomic writes prevent torn state. |
| Ship → LEDGER.md | The ledger is the cross-session memory; corruption or duplication breaks future context injection. |
