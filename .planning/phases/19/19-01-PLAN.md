**TD-1 (closeOnces sync.Map → per-channel struct):**
In `internal/tui/app.go`, replace the global `var closeOnces sync.Map` (line 462) and the `safeCloseOnce` function (lines 464-476) with a per-channel approach. Define a new unexported struct `channelCloser` that wraps `chan struct{}` with an embedded `sync.Once`:

```go
type channelCloser struct {
    ch   chan struct{}
    once sync.Once
}
```

The `safeCloseOnce` function signature stays the same (`func safeCloseOnce(ch chan struct{}) bool`), but internally it stores a `*channelCloser` in the sync.Map keyed by the channel pointer. This is semantically equivalent but documents the intent. Actually, per the locked decision: replace the global sync.Map with per-channel sync.Once stored in a wrapper struct. The wrapper holds the channel + Once together, eliminating the global map entirely.

New approach: Change `safeCloseOnce` to accept `*channelCloser` instead of `chan struct{}`. Update all call sites in `app.go` to use `*channelCloser` fields. The `msgDone` field changes from `chan struct{}` to `*channelCloser`. This eliminates the global `closeOnces` sync.Map entirely. Each `channelCloser` is created fresh per phase in `RunPhaseCmd`.

Add a `newChannelCloser()` helper function that creates a new `channelCloser` with an open channel.

In `internal/config/loader.go`, replace the manual `mergeConfig` function (lines 118-269) with a reflection-based approach. The new implementation uses `reflect` to iterate over struct fields, copying non-zero overlay values to base. Handle nested structs recursively. Special cases:
- Slices: replace if non-nil and non-empty (copy entire slice, not append)
- Maps: merge entries (overlay entries override base entries)
- Strings: copy if non-empty
- Bools: copy if true (since false is the zero value and means "use default")
- Ints/floats: copy if non-zero
- Add `"log/slog"` import and log at debug level for each override
