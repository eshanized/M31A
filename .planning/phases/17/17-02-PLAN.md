### Task 2: Fix Grep truncation messages (H-2, H-3)

**read_first:**
- `internal/tools/grep.go`
- `internal/tools/grep_test.go`

**action:**
Fix truncation message calculation in both `grepWithRG` and `grepPureGo`:

1. In `grepWithRG`: The loop exits when `count >= maxResults`, so `count-maxResults` is always 0. Instead, after the loop, check if `scanner.Scan()` returned true (meaning there are more results). If so, set `truncated = true` and use a message like `"[... more matches (limit: %d)]"`.

2. In `grepPureGo`: Same issue — `len(results)-maxResults` is always 0. Track whether `filepath.SkipAll` was returned (meaning there were more matches) and adjust the message accordingly.

**acceptance_criteria:**
- When >100 matches exist, truncation message says "[... more matches (limit: 100)]"
- When exactly 100 matches exist, no truncation message
- `TestGrep_RG_TruncationMessage` passes
- `TestGrep_PureGo_TruncationMessage` passes

### Task 6: Fix Engine.consumeStream error handling (H-7)

**read_first:**
- `internal/workflow/engine.go`

**action:**
In `consumeStream()`, check for errors before appending chunk delta. When `Next()` returns both a chunk and an error:
1. If the chunk has content, log it or append it (partial content is valuable)
2. If the error is not EOF, return the error
3. If the error is EOF, finalize the message

The current code appends the delta then breaks on error, which can lose partial content if the error is propagated.

**acceptance_criteria:**
- Partial content before non-EOF errors is preserved in the message
- `TestConsumeStream_ErrorBeforeEOF` passes
- `go test ./internal/workflow/...` exits 0
