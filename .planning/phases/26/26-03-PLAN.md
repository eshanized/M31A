# Plan 26-03 — ScreenDiscuss Implementation

## Objective

Implement `ScreenDiscuss` (enum value 14) as a dedicated discuss phase Q&A screen that replaces the current inline-in-REPL approach. The screen shows a progress indicator (question N of M), the current question with a text input, a 5-minute timeout timer, and skip/answer buttons.

## read_first

- `internal/tui/types.go` — Screen enum (ScreenDiscuss = 14), DiscussAnswerTimeoutMsg, QuestionRequestMsg
- `internal/tui/app_view.go` — View() switch statement
- `internal/tui/app_update.go` — Update() screen dispatch, DiscussAnswerTimeoutMsg handling
- `internal/tui/app_update_workflow.go` — handlePhaseDiscuss(), askNextDiscussQuestion(), finalizeDiscussAndAdvance()
- `internal/tui/goalinput.go` — Reference for full-screen input layout
- `internal/tui/components/progress.go` — ProgressBar component for progress indicator
- `internal/tui/components/question.go` — QuestionModel for inline question rendering
- `internal/tui/theme/theme.go` — Theme struct

## action

### 1. Create `internal/tui/discuss.go`

Create a new file implementing `DiscussModel`:

```go
type DiscussModel struct {
    theme           theme.Theme
    width           int
    height          int
    questions       []string          // all questions from discuss phase
    currentIndex    int               // current question index (0-based)
    answers         map[int]string    // collected answers
    textInput       textarea.Model    // answer input
    timer           int               // seconds remaining (300 = 5 min)
    timerActive     bool
    skipped         bool              // user chose to skip remaining
    questionCount   int               // total questions
    sessionID       string
}
```

### 2. Implement methods

- `NewDiscussModel(t theme.Theme, questions []string, width, height int) *DiscussModel` — initialize with first question focused
- `Init() tea.Cmd` — return textarea.Blink
- `Update(msg tea.Msg) ([]tea.Cmd, *AppMsg)` — handle:
  - `WindowSizeMsg`: resize
  - `tea.KeyMsg`:
    - `Enter`: submit answer, advance to next question or finalize
    - `Tab`: switch focus between text input and skip button
    - `Esc`: skip remaining questions
    - `ctrl+c`: cancel discuss phase
  - `DiscussAnswerTimeoutMsg`: auto-skip current question
  - `Spinner.TickMsg`: timer countdown
- `View() string` — render:
  - Header: "Discuss — Question {N}/{M}"
  - Progress bar: `ProgressBar{current, total}`
  - Timer: "⏱ {mm:ss} remaining" (red when < 60s)
  - Question text (centered, styled with `theme.Brand`)
  - Text input area (60% width, centered)
  - Bottom: `[Enter] Submit · [Tab] Skip · [Esc] Skip All`

### 4. Wire into app_update.go

```go
case ScreenDiscuss:
    cmds := []tea.Cmd{permissionListenerCmd(m.shutdownCtx, m.dispatcher), questionListenerCmd(m.shutdownCtx, m.dispatcher)}
    if m.discussModel != nil {
        subCmds, appMsg := m.discussModel.Update(msg)
        if appMsg != nil {
            m.screen = appMsg.Screen
            // If discuss completed, advance to plan phase

                m.setWorkflowPhase(types.PhasePlan)
                cmds = append(cmds, RunPhaseCmd(m, types.PhasePlan, m.workflowGoal))
            }

        cmds = append(cmds, subCmds...)
    }
    return m, tea.Batch(cmds...)
```

### 5. Modify handlePhaseDiscuss in app_update_workflow.go

Replace the current inline REPL approach with ScreenDiscuss transition:

```go
func handlePhaseDiscuss(m *AppState, msg PhaseResultMsg) (tea.Model, tea.Cmd) {
    // ... existing question extraction ...
    
    if !msg.NeedsAnswers || len(questions) == 0 {
        // No questions needed — skip to plan
        m.setWorkflowPhase(types.PhasePlan)
        return m, RunPhaseCmd(m, types.PhasePlan, m.workflowGoal)
    }
    
    // Transition to ScreenDiscuss
    m.discussModel = NewDiscussModel(m.themeManager.Current(), questions, m.width, m.height)
    m.screen = ScreenDiscuss
    m.setWorkflowPhase(types.PhaseDiscuss)
    m.persistWorkflowState()
    return m, m.discussModel.Init()
}
```
