### Fix WIR-04: Diff Screen Split View Toggle

In `diff.go`, the `splitView` field exists but is never used. Implement the toggle:

1. In `Update()`, add key handler:
   ```go
   case "v", "V":
       m.splitView = !m.splitView
   ```

2. In `View()`, add split view rendering:
   ```go
   func (m *DiffModel) renderSplitView() string {
       leftWidth := m.width / 2
       rightWidth := m.width - leftWidth - 1
       
       leftContent := m.renderFileList(leftWidth)
       rightContent := m.renderDiffContent(rightWidth)
       
       return lipgloss.JoinHorizontal(lipgloss.Top, leftContent, "│", rightContent)
   }
   ```

3. Update View() to dispatch based on `splitView`:
   ```go
   if m.splitView {
       return m.renderSplitView()
   }
   return m.renderUnifiedView()
   ```

4. Add `[V] Split View` to the bottom bar.

### Fix WIR-06: GoalInput PhaseInitialize

In `goalinput.go`, the `Update()` method transitions directly to PhaseDiscuss. Fix by inserting PhaseInitialize:

1. Find where the goal is submitted (Enter key handler):
   ```go
   case "enter":
       if m.textInput.Value() != "" {
           goal := m.textInput.Value()
           // OLD: return to REPL, start Discuss
           // NEW: start Initialize phase first
           return []tea.Cmd{func() tea.Msg {
               return GoalSubmittedMsg{Goal: goal}
           }}, nil
       }
   ```

2. In `app_update.go`, handle `GoalSubmittedMsg`:
   ```go
   case GoalSubmittedMsg:
       m.workflowGoal = msg.Goal
       m.setWorkflowPhase(types.PhaseInitialize)
       m.screen = ScreenREPL
       return m, RunPhaseCmd(m, types.PhaseInitialize, m.workflowGoal)
   ```

3. `handlePhaseInitialize()` already exists and handles project detection, git init, and PROJECT.md creation. It then triggers Discuss. So the chain is: GoalInput → PhaseInitialize → PhaseDiscuss → ScreenDiscuss.

### Fix WIR-07: Metrics Sparkline

   // Compute sparkline data from daily usage

       m.sparklineData[i] = float64(entry.Tokens)
   }

3. In `renderDailyUsage()`, add sparkline above the bar chart:

   func (m *MetricsModel) renderDailyUsage() string {
       // ... existing bar chart code ...
