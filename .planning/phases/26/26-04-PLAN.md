# Plan 26-04 — Plan/Execute/Verify Wiring Fixes

## Objective

Fix three moderate wiring issues in the workflow screens: replace placeholder cost estimation in Plan, wire Execute pause/resume to the workflow engine, and make Verify self-heal trigger actual re-verification.

## read_first

- `internal/tui/plan.go` — PlanModel, cost estimation in View(), ApplyArbitrage()
- `internal/tui/execute.go` — ExecuteModel, paused field, P/R key handlers
- `internal/tui/verify.go` — VerifyModel, healFunc callback, SetHealFunc()
- `internal/tui/app_update_workflow.go` — handlePhasePlan(), handlePhaseExecute(), handlePhaseVerify()
- `internal/tui/app.go` — AppState struct, workflowEngine interface
- `pkg/arbitrage/arbitrage.go` — ArbitrageRecommendation, cost estimation
- `internal/provider/interface.go` — LLMProvider.EstimateCost()

## action

### Fix WIR-01: Plan Screen Cost Estimation

In `plan.go`, replace the placeholder cost string with real cost estimation:

1. Add `estCost float64` field to PlanModel (already exists)
2. In `NewPlanModel()`, accept and store the cost estimate
3. In `View()`, replace `fmt.Sprintf("%d tasks", len(m.tasks))` with:
   ```go
   costStr := fmt.Sprintf("$%.4f", m.estCost)
   if m.estCost == 0 {
       costStr = "—"
   }
   ```
4. In `handlePhasePlan()`, compute actual cost from `msg.Usage` and provider pricing:
   ```go
   estCost := 0.0
   if msg.Usage != nil && m.activeModel != nil {
       estCost = m.activeModel.Pricing.InputPerMToken * float64(msg.Usage.PromptTokens) / 1_000_000
       estCost += m.activeModel.Pricing.OutputPerMToken * float64(msg.Usage.CompletionTokens) / 1_000_000
   }
   ```

### Fix WIR-02: Execute Screen Pause/Resume

1. In `execute.go`, the `P` key handler already sets `m.paused = !m.paused`. Wire this to the workflow engine:
   ```go
   case "p", "P":
       m.paused = !m.paused
       // Emit a message that AppState handles
       return []tea.Cmd{func() tea.Msg {
           return ExecutePauseMsg{Paused: m.paused}
       }}, nil
   ```
2. In `app_update.go`, handle `ExecutePauseMsg`:
   ```go
   case ExecutePauseMsg:
       if m.workflowEngine != nil {
           if msg.Paused {
               m.workflowEngine.Pause()  // if method exists
           } else {
               m.workflowEngine.Resume() // if method exists
           }
       }
       return m, nil
   ```
3. If `workflowEngineInterface` doesn't have Pause/Resume methods, add them:
   ```go
   type workflowEngineInterface interface {
       // ... existing methods ...
       Pause()
       Resume()
   }
   ```
4. In `execute.go`, the `R` key handler should similarly emit `ExecutePauseMsg{Paused: false}`

### Fix WIR-03: Verify Screen Self-heal Re-verification

In `verify.go`, modify `SetHealFunc` and the heal confirmation handler:

1. Change `healFunc` signature to return a `tea.Cmd` that triggers re-verification:
   ```go
   type HealResult struct {
       TaskID  int
       Success bool
   }
   
   healFunc func(taskID int) tea.Cmd
   ```

2. In the heal confirmation handler (`y/Y/enter` case):
   ```go
   case "y", "Y", "enter":
       if m.healFunc != nil {
           cmd := m.healFunc(m.confirmHealTask)
           m.confirmHeal = false
           // Set task status to running while heal is in progress
           for i := range m.tasks {
               if m.tasks[i].ID == m.confirmHealTask {
                   m.tasks[i].Status = types.StatusRunning
                   break
               }
           }
           return []tea.Cmd{cmd}, nil
       }
   ```

3. In `handlePhaseVerify()`, update the heal callback to trigger re-verification:
   ```go
   m.verifyModel.SetHealFunc(func(taskID int) tea.Cmd {
       return func() tea.Msg {
           if m.workflowEngine != nil {
               success := m.workflowEngine.HealTask(taskID)
               return HealResultMsg{TaskID: taskID, Success: success}
           }
           return HealResultMsg{TaskID: taskID, Success: false}
       }
   })
   ```

4. Add `HealResultMsg` to `types.go`:
   ```go
   type HealResultMsg struct {
       TaskID  int
       Success bool
   }
   ```

5. Handle `HealResultMsg` in `app_update.go` to update task status and potentially re-run verification
